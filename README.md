# 背包排布问题 · Backpack Layout (深空当铺模组求解器)

在带禁用格的小棋盘上摆放不规则形状的物品和不限数量的 1×2 特殊矩形，求**全局最优**的摆法，并**证明**不存在更好的合法方案。支持三个属性（性能、质量、效率）、达标条件、负值和必选物品。

**在线使用：<https://packsolver.site>**

计算全部在浏览器本地完成（Rust 编译成 WebAssembly，多线程），数据不会上传。

## 浏览器支持

求解依赖 WebAssembly 多线程（SharedArrayBuffer + 跨源隔离 + 模块 Worker），需要使用以下内核的浏览器：

| 内核 | 最低版本 | 常见浏览器 |
|---|---|---|
| Chromium | 92 | Chrome、Edge（电脑和安卓） |
| WebKit | Safari 15.2 | Safari；iPhone / iPad 上的所有浏览器（iOS 上都使用 WebKit） |
| Gecko | Firefox 114 | Firefox |

**不支持**：微信 / QQ 内置浏览器、UC / 夸克浏览器，以及部分手机厂商自带的浏览器（如一加）。这些浏览器的定制内核不支持跨源隔离，打开后会提示"未启用跨源隔离"。请复制链接到 Chrome、Edge 或 Safari 中打开。

## 规则

- 棋盘 W×H，部分格子禁用。物品可旋转、镜像，不能重叠、不能越界、不能占禁用格；每个物品最多用一次。
- 内置 7 种形状：`U` 凹形、`F`、`L`、`T`、`O` 方形、`V` 小 L、`I` 1×4 长条；网页上还可以在 3×3 格子里画自定义形状。
- 每个物品有三个属性：**性能、质量、效率**，都是整数，可以为负。三个属性各自独立、按同样的规则计分：
  - **边界奖励**：物品接触指定的那条棋盘边（上/下/左/右），+20%。
  - **邻接奖励**：开启后，每与一个不同的特殊矩形相邻（上下左右，对角不算），+10%。
  - 一个物品的两种奖励**先合并再向零取整**：`值 + trunc(值 × (2·贴边 + 相邻矩形数) / 10)`。例如 -56 贴边：-56 + trunc(-11.2) = -67。
  - **特殊矩形**（1×2，可横可竖，不限数量，本身无基础值）：相邻普通物品的基础值**先求和**，再取 20% 向零取整。
- **求解目标**：恰好一个属性"求最大"；其余属性可以设"达标值"（总和 ≥ 目标）或"跳过"。达不到时会提示无法达标，并给出每个达标属性单独能达到的最大值。
- **必选物品**：标记为必选的物品一定会被放上；放不下时提示。

## 算法

1. **逐格扫描的动态规划**：沿棋盘短边逐格决定"留空 / 放特殊矩形 / 放某物品的某姿态"，每种布局只生成一次。邻接关系出现时立即计入"新取整值 − 旧取整值"，逐项相消后恰好等于最终值（负值、跨零都精确）。没有负值的属性上，未结算实体只需保留余数。
2. **支配剪枝**：同一几何局面下，如果 A 用过的物品是 B 的子集、必选物品使用情况相同，并且在每个属性上，A 的领先都不少于 B 的未结算实体未来最多还能多拿的分数（可证明的上界），A 就支配 B（Pareto 前沿）。达标属性在没有负值时累计到目标就封顶。
3. **达标条件先放宽**：先不考虑达标条件求一次，最优解恰好满足条件时就是答案；否则再带着条件完整求解。
4. **懒约束**：先允许物品重复使用求松弛上界，只对实际被超量使用的物品加"最多一次"的限制再求解，直到松弛最优解本身合法——它就是可证明的全局最优。
5. **并行**：状态按键哈希分 64 片，每层分批用 rayon 并行展开、按分片无锁插入。
6. **预筛选**：同一形状、同样边界和邻接设置的物品最多只能放下 k 个（k = 空格数 ÷ 面积）。如果某物品在所有参与计算的属性上都不比另外至少 k 个强，它就不可能出现在最优解里，求解前直接去掉（不影响最优性）。

### 快速模式（近似）

在同样的逐格扫描上做**束搜索**：每层只保留最有希望的若干个状态（最多 5000 个），计分规则与精确模式完全相同，结果同样经过校验器检查，但**不保证最优**，条件很紧时也可能找不到满足所有达标条件的方案。
- 状态打分：求最大的属性 + 对剩余空格的乐观估计（用还没用过的物品按每格价值从高到低填满，未放的必选物品必须算进去）+ 权重 × 各达标属性朝目标的进度（达到目标后不再加分）。有达标条件时跑两遍（一遍只看已达到的进度、推得更猛，一遍把乐观估计也算进进度、避免走进死胡同），取最好的结果。
- 物品很多时，一次只搜索按每格价值精选的 40 件（束可以更宽），另一次搜索全部物品，取两者中更好的。
- 精确模式在去掉不可能用上的物品后最多处理 63 件；快速模式最多 255 件，更多时按每格价值贪心保留（必选物品始终保留）。
- 实测（原生）：13～20 件物品约 0.5～2.5 秒，多数实例恰好等于精确最优（20 件基准 477 = 最优）；600 件物品约 2～4 秒。小棋盘随机对拍中全部找到可行解，绝大多数恰好最优。

正确性由独立校验器（按规则直接重算总分）和小棋盘上与暴力穷举的随机对拍保证（含负值、达标条件、必选物品）。

## 使用

### 网页版（推荐）

```bash
cd web
node serve.mjs          # 打开 http://localhost:8080
```

网页需要 COOP/COEP 响应头才能启用 WASM 多线程，所以请用自带的 `serve.mjs`，不要直接双击打开 `index.html`。
部署到 Cloudflare Pages / Netlify 时 `_headers` 会自动生效；其他平台（如腾讯云 COS + CDN）需要在 CDN 上配置：

```
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

且必须使用 HTTPS。网址后加 `?threads=N` 可以限制使用的 CPU 核数。

默认开启「快速模式」，几秒内给出近似解（标注为「近似解 · 未证明最优」）；关闭后求可证明的全局最优解，但可能要几分钟，物品多或有多个达标条件时可能超出浏览器内存。

当前物品列表可以输入组名后保存为预设组（含数量、必选；保存在浏览器本地），之后在"我的预设组"里点一下组名即可整组载入，替换当前列表。

### 重新编译 WASM

需要 Rust nightly（含 `rust-src`、`wasm32-unknown-unknown` 目标）以及与 `solver-rs/Cargo.toml` 中版本一致的 `wasm-bindgen-cli`：

```bash
cd web
node build-wasm.mjs     # 输出到 web/pkg
```

### 原生命令行（测速 / 测试）

```bash
cd solver-rs
cargo test --release
cargo run --release --bin bench -- ../examples/shapes20_1.json
```

## 输入格式

```json
{
  "width": 7, "height": 5,
  "blocked": [[0,0],[6,0],[0,4],[6,4]],
  "goal": {"performance": "max", "quality": 100, "efficiency": "skip"},
  "items": [
    {"name": "凹", "type": "U", "performance": 56, "quality": 30, "efficiency": -10, "adjBonus": true},
    {"name": "F1", "type": "F", "performance": 45, "quality": 20, "border": "top", "required": true}
  ]
}
```

- 坐标为 `[x, y]`，原点在左上角。物品用 `type`（内置形状）或 `shape`（格子坐标列表）二选一。
- `goal` 里每个属性取 `"max"`（恰好一个）、`"skip"` 或一个数字（达标值）；省略时为性能求最大。没写的属性视为 0。
- 旧格式的 `value` 等同于 `performance`。
- 可选 `"mode": "fast"` 使用快速模式（默认 `"exact"`）。输入最多 5000 件物品。
